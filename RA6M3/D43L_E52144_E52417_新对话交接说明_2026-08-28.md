## 1. 当前目标

在D43L（RA6M3）上完成以下功能：

1. 上电后初始化E521.44，并通过DSI0识别E524.17。
2. 使用D43L板上的P001按钮触发测量。
3. 每按一次按钮只执行一次标准超声波测量。
4. 从25个PDCM帧中解析E524.17的F6/F7回波。
5. 选择最早的有效TLH（EchoType=0）计算距离。
6. 通过SCI9把测量结果打印到电脑串口软件。

## 3. 硬件连接

### 3.1 D43L与E521.44

| D43L | E521.44 | 说明 |
| --- | --- | --- |
| P411 | MOSI | SPI0 MOSI |
| P410 | MISO | SPI0 MISO |
| P412 | SCK | SPI0时钟 |
| P413 | CSB | GPIO片选，低有效 |
| P504 | CLKREF | GPT13输出500 kHz、50%占空比 |
| P708 | RESB | 复位输出，低有效 |
| P508 | RFC | 就绪输入 |
| P307 | INTB | 中断状态输入，低有效 |
| P200 | DAB | PDCM数据可用输入，低有效 |
| 3.3 V | MCU_VCC | 数字电源 |
| GND | GND | 共地 |

E521.44还需要12 V电源，12 V、3.3 V和GND均必须正确连接。

### 3.2 E521.44与E524.17

- 当前使用E521.44的CN2，即DSI0。
- CN1对应DSI1，CN2对应DSI0，丝印容易混淆。
- E524.17三线接口：1电源、2 DSI3、3 GND。

### 3.3 UART与按钮

| 功能 | 引脚 |
| --- | --- |
| P001按钮 | P001，GPIO输入，按下为低电平 |
| SCI9 TXD | P109 |
| SCI9 RXD | P110 |

USB转串口连接：

```text
P109/TXD9  → USB转串口RXD
P110/RXD9  ← USB转串口TXD
GND        ↔ USB转串口GND
```

使用3.3 V TTL电平，不要向P109/P110接入5 V。

## 4. FSP配置现状（2026-08-28已检查）

### 4.1 已落实

- `g_spi0`：SPI0，500 kbit/s，主机模式，回调`spi_callback`。
- `g_clkref_timer`：GPT13，在P504输出500 kHz参考时钟。
- `g_uart0`：UART on SCI9。
- UART参数：115200、8数据位、无校验、1停止位。
- UART回调：`uart_callback`。
- UART中断优先级：RXI/TXI/TEI/ERI均为Priority 12。
- P109已生成成`SCI9_TXD_MOSI`。
- P110已生成成`SCI9_RXD_MISO`。
- P001已生成成GPIO输入：`P001 ... GPIO ... Input mode`。
- Debug接口已经改为SWD，P109/P110不再被JTAG占用。
- UART Flow Control Support为0，因此不需要RTS/CTS线；界面中显示Hardware RTS可以保留。

### 4.2 串口软件参数

```text
Baud rate: 115200
Data bits: 8
Parity: None
Stop bits: 1
Flow control: None
```

## 5. 当前代码状态

当前`hal_entry.c`已经从“表达式窗口调试版”改为“按钮单次测量+串口输出版”。

### 5.1 已删除/收拢的调试数据

原来的大量`volatile g_e524_*`调试数组已删除。仍保留的PDCM原始缓冲区改为文件内`static`变量，只用于读取25帧和后续解析。

最终结果使用结构体保存：

```c
typedef struct st_e524_measurement_result
{
    bool valid;
    uint8_t address;
    uint8_t frame_number;
    uint16_t packet_index;
    uint16_t time_us;
    uint16_t echo_height;
    uint32_t distance_cm_x100;
} e524_measurement_result_t;
```

### 5.2 上电流程

`hal_entry()`当前执行：

```text
打开SCI9 UART
→ 输出启动信息
→ 启动GPT13 CLKREF
→ RESB拉低5 ms
→ 检查RFC低电平
→ 释放RESB并等待RFC高电平
→ 打开SPI0
→ 清除E521.44中断状态
→ 配置DSI_CFG=0x31（3 μs Chip Time）
→ 扫描E524.17物理地址1～6
→ 上传并验证单传感器TDMA
→ 输出READY信息
→ 主循环等待P001按钮
```

### 5.3 按钮流程

- 轮询P001。
- 按下为低电平。
- 使用20 ms软件消抖。
- 按钮释放后才返回一次“已按下”，避免长按重复测量。
- 每次有效按键调用`E52144A_MeasureOnce()`。

### 5.4 单次测量流程

```text
发送STA标准测量命令
→ 启动25个PDCM周期
→ 每帧等待DAB变低
→ 读取1个16-symbol PDCM帧
→ 共读取25帧
→ 解析F6/F7
→ 选择最早有效TLH
→ 通过SCI9打印结果
```

正常串口输出格式：

```text
[RESULT] addr=1, frame=F7, packet=7, time=706 us, height=80, distance=12.00 cm
```

无TLH时输出：

```text
[RESULT] No valid TLH echo.
```

### 5.5 回波有效性规则

- TDMA符号数：16。
- PDCM读取数量：25帧。
- 解析格式：E524.17 F6/F7。
- `EchoType=0`为TLH。
- 遍历全部帧后选择时间戳最小的有效TLH。
- 只把`ComErr=1`判为通信无效。
- `HwErr=1、ComErr=0`时仍允许解析回波，避免历史HwErr导致所有数据被丢弃。

距离计算：

```text
distance_cm = time_us × 340 / 20000
```

代码使用整数保存`distance_cm_x100`，串口输出两位小数，不依赖浮点格式化支持。

### 5.6 CRM等待时间

当前定义：

```c
#define E52144_CRM_RESPONSE_WAIT_US (20000U)
```

发送CRM后等待20 ms再读取CRM，这是根据现场建议临时拉长的诊断值。

注意：当前`E52144A_ResponseCRM()`在SPI读取已经完成后还额外等待了20 ms，然后才解析本地`RxData`。这第二次等待不会改变已经读到的内容，可能是多余的。新对话应先检查`hal_entry.c`约650～680行，再决定是否删除读取后的第二个20 ms等待；不要改动发送CRM与读取CRM之间的20 ms等待。

## 7. 已知问题与结论

### 7.1 SPI偶发失败、重新上电后恢复

原因曾是SPI寄存器读取帧没有用CRC命令正确结束，使E521.44内部CRC状态与下一条命令不同步。当前所有SPI帧均应以CRC命令和计算出的CRC结束。发生异常时需要完整重新上电验证。

### 7.2 CN1/CN2通道问题

CN1=DSI1，CN2=DSI0。当前软件使用DSI0，因此应接CN2。

### 7.3 CRM无响应

`RxData[2]=0x2000`表示响应符号数为0；有效CRM响应时曾得到`RxData[2]=0x0008`。需要检查物理地址、通道、供电、DSI3连接和发送/读取间隔。

### 7.4 HwErr=1

诊断曾得到：

```text
HwErrStatusInfo1 = 0x0001
HwErrStatusInfo2 = 0x0000
```

对应Watchdog reset（Class 4）。当前做法不是清除E524.17内部HwErr，而是当`ComErr=0`时仍允许解析回波。

E521.44初始化时使用：

```c
E52144A_WriteRegister(IRQ_STST,     0x1007U);
E52144A_WriteRegister(BUF_IRQ_STAT, 0x007FU);
```

这两行用于清除E521.44中断和缓冲区状态，不等同于清除E524.17的HwErr。

### 7.5 近距离一直约12 cm

12 cm对应约706 μs。如果实际目标更近但结果锁定在该值，可能是近场振铃、直接测量屏蔽时间或固定结构反射，不能仅凭这个数值认定目标就在12 cm。应观察TLH时间戳，并用大平板从30 cm逐步向内移动验证最小可靠距离。

### 第三步：根据现象排查

- 完全没有串口文字：检查P109/P110交叉接线、GND、COM口、115200参数和UART回调。

- 显示`No valid TLH echo`：检查F6/F7帧、EchoType、目标位置和近场振铃。
- 按下后程序卡住：重点检查等待DAB变低的循环，目前该循环没有超时退出机制。
