## 二、RA6M3 LCD 显示系统学习

### 2.1 显示系统基本配置

本次学习对象为 D43L 工程中的 480 × 272 RGB 屏幕，主要配置如下：

| 项目 | 配置 | 通俗理解 |
| --- | --- | --- |
| 分辨率 | 480 × 272 | 每行 480 个像素，共 272 行 |
| 显示接口 | RGB 并行接口 | 使用多根数据线同时传输颜色数据 |
| 显示控制器 | RA6M3 内部 GLCDC | 按照设定的显示时序持续向屏幕输出画面 |
| 显存像素格式 | RGB565 | RAM 中每个像素占 2 字节 |
| 输出像素格式 | RGB888 | 向屏幕输出 24 位 RGB 颜色数据 |
| 背光控制 | P100，经背光驱动电路控制 | 通过开关或 PWM 调节屏幕亮度 |

整个显示过程可以理解为：

```text
程序决定需要显示的内容
          ↓
CPU 修改 RAM 中的帧缓冲区
          ↓
GLCDC 按固定时序读取帧缓冲区
          ↓
通过 RGB 并行接口输出像素和同步信号
          ↓
LCD 按行、按帧扫描并显示图像
```

程序通常把屏幕左上角定义为坐标原点 `(0, 0)`，水平方向为 X 轴，垂直方向为 Y 轴。对于 480 × 272 的屏幕，有效坐标范围为：

```text
X：0～479
Y：0～271
```

### 2.2 RGB 颜色的构成

屏幕上的颜色由红、绿、蓝三个分量组合而成：

| 红色分量 | 绿色分量 | 蓝色分量 | 得到的颜色 |
| --- | --- | --- | --- |
| 最低 | 最低 | 最低 | 黑色 |
| 最高 | 最低 | 最低 | 红色 |
| 最低 | 最高 | 最低 | 绿色 |
| 最低 | 最低 | 最高 | 蓝色 |
| 最高 | 最高 | 最高 | 白色 |
| 最高 | 最高 | 最低 | 黄色 |

程序使用数字表示每个颜色分量的强弱，三个分量组合后得到最终像素颜色。

#### RGB565

RGB565 使用 16 个二进制位表示一个像素：

```text
红色 5 位 + 绿色 6 位 + 蓝色 5 位 = 16 位
```

常用颜色值如下：

| 颜色 | RGB565 十六进制值 |
| --- | --- |
| 黑色 | `0x0000` |
| 白色 | `0xFFFF` |
| 红色 | `0xF800` |
| 绿色 | `0x07E0` |
| 蓝色 | `0x001F` |

#### RGB888

RGB888 使用 24 位表示一个像素，红、绿、蓝各占 8 位。D43L 工程在 RAM 中使用 RGB565 保存画面，再由 GLCDC 按 RGB888 的接口格式输出到屏幕。

这种方式可以节省帧缓冲区占用，但 RGB565 转换为 RGB888 只是在输出格式上扩展位数，并不会增加原始画面的颜色精度。由此可见，**显存中的像素格式不一定等于屏幕接口的输出格式**。

### 2.3 帧缓冲区与显存占用

帧缓冲区（Frame Buffer）是 MCU RAM 中用于存放整幅画面像素数据的区域。“一帧”就是一幅完整画面。

以 480 × 272、RGB565 为例，每个像素占 2 字节，因此一帧需要：

```text
480 × 272 × 2
= 261120 字节
= 255 KiB
```

CPU 负责修改帧缓冲区中的像素，GLCDC 则持续读取这些数据并送往屏幕。两者的分工如下：

| 部分 | 主要工作 |
| --- | --- |
| CPU 与应用程序 | 决定画什么，并修改帧缓冲区 |
| GLCDC | 持续读取帧缓冲区，按显示时序输出画面 |
| LCD | 接收 RGB 数据和时序信号，显示最终图像 |

### 2.4 RGB 屏幕的主要时序信号

RGB 屏幕并不会直接收到 `(x, y)` 坐标，而是根据像素时钟、同步信号和有效数据区域，判断当前数据属于哪一行、哪一个像素。

| 信号 | D43L 引脚 | 作用 |
| --- | --- | --- |
| `LCD_DCLK` | P101 | 像素时钟 |
| `LCD_DISP` | P102 | 屏幕显示使能 |
| `LCD_DE` | P103 | 表示当前 RGB 数据是否有效 |
| `LCD_VS` | P104 | 垂直同步，标记一帧画面的边界 |
| `LCD_HS` | P105 | 水平同步，标记一行像素的边界 |
| `LCD_DB0～DB23` | 多个引脚 | 传输红、绿、蓝颜色数据 |

本工程像素时钟 DCLK 为 10 MHz，屏幕在上升沿采样 RGB 数据。

#### 水平时序 HSYNC

HSYNC 是水平同步信号，用来表示一行扫描结束，即将开始下一行。输出一行时，除了 480 个有效像素，还包括同步脉冲和前后间隔：

| 水平阶段 | 像素时钟数 |
| --- | ---: |
| HSYNC 脉冲 | 4 |
| 后沿 Back Porch | 43 |
| 有效显示区 | 480 |
| 前沿 Front Porch | 4 |
| 一行合计 | 531 |

```text
4 + 43 + 480 + 4 = 531 个像素时钟

一整行：
┌────────┬──────────┬────────────────────────────┬────────┐
│ HSYNC  │   后沿   │        有效像素区域        │  前沿  │
│ 4 周期 │ 43 周期  │         480 周期           │ 4 周期 │
└────────┴──────────┴────────────────────────────┴────────┘
                       DE = 高电平
```

- **后沿 Back Porch**：同步脉冲结束后，到有效图像开始前的等待时间。
- **前沿 Front Porch**：有效图像结束后，到下一次同步脉冲前的等待时间。

这些间隔属于屏幕时序，并不是程序需要绘制的黑色像素。

#### 垂直时序 VSYNC

VSYNC 是垂直同步信号，用来表示一帧扫描结束，即将从屏幕顶部重新开始。D43L 旧工程的垂直参数如下：

| 垂直阶段 | 行数 |
| --- | ---: |
| VSYNC 脉冲 | 4 |
| 后沿 Back Porch | 12 |
| 有效显示区 | 272 |
| 前沿 Front Porch | 4 |
| 一帧合计 | 292 |

```text
4 + 12 + 272 + 4 = 292 行

一整帧：
┌────────┬──────────┬────────────────────────────┬────────┐
│ VSYNC  │   后沿   │        有效画面区域        │  前沿  │
│  4 行  │  12 行   │          272 行            │  4 行  │
└────────┴──────────┴────────────────────────────┴────────┘
```

一行共有 531 个像素时钟，在 10 MHz DCLK 下约为 53.1 μs；一帧共有 292 行，因此：

```text
53.1 μs × 292 ≈ 15.5 ms
刷新率 ≈ 1 ÷ 0.0155 s ≈ 64.5 Hz
```

也就是屏幕每秒大约重新扫描 64.5 次完整画面。

#### 数据使能 DE

DE（Data Enable）用来告诉屏幕当前 RGB 数据是否属于有效画面：

```text
DE 为高电平：RGB 数据有效，屏幕显示这些像素
DE 为低电平：处于同步或间隔区域，RGB 数据不显示
```

一行中的关系可以简化为：

```text
HSYNC：___|脉冲|____________________________________
DE：   ____________|‾‾‾‾‾‾有效 480 像素‾‾‾‾‾‾|____
RGB：  无效数据     | P0 P1 P2 ... P478 P479   |无效
DCLK：持续输出像素时钟
```

DE 变高后，第 1 个有效 DCLK 对应 `x=0`，第 480 个有效 DCLK 对应 `x=479`。垂直方向同理，第 1 个有效行对应 `y=0`，第 272 个有效行对应 `y=271`。

### 2.5 动态帧缓冲区与画面撕裂

动态帧缓冲区的基本思路是：GLCDC 保持运行，CPU 直接修改 GLCDC 正在读取的帧缓冲区，随后屏幕便会显示新的内容。

如果只有一个帧缓冲区，CPU 修改画面的同时，GLCDC 可能正在扫描同一块内存。这时屏幕上半部分可能来自旧画面，下半部分来自新画面，从而出现“撕裂”。

当前通过 GLCDC 的行检测事件设置同步标志，让 CPU 尽量在每帧的固定时刻集中修改显存：

```c
static volatile bool g_vsync_ready = false;

void glcdc_callback(display_callback_args_t * p_args)
{
    if ((NULL != p_args) &&
        (DISPLAY_EVENT_LINE_DETECTION == p_args->event))
    {
        g_vsync_ready = true;
    }
}

static void lcd_wait_vsync(void)
{
    g_vsync_ready = false;

    while (!g_vsync_ready)
    {
        /* 等待下一次帧同步 */
    }
}
```

这种方式能够减少撕裂。如果后续画面更新量较大，还可以进一步采用双帧缓冲，在后台缓冲区完成绘制后，于帧边界切换显示地址。

## 三、ADAS/APA 传感器生态链学习

### 3.1 不同传感器的功能分工

ADAS 系统会根据探测距离、目标类型和应用场景组合摄像头、毫米波雷达、激光雷达和超声波传感器。不同传感器在车辆周围形成互补的感知范围：

![ADAS 车辆周围传感器覆盖范围](picture/Pasted%20image%2020260909170609.png)

- **摄像头**：擅长识别车道线、交通标志、车辆和行人等视觉信息。
- **毫米波雷达**：适合中远距离探测，并可利用多普勒效应测量目标速度。
- **激光雷达**：能够获得较高精度的三维距离信息。
- **超声波传感器**：适合近距离障碍物检测，主要应用于倒车辅助和 APA 自动泊车。

毫米波雷达和超声波传感器的特点对比如下：

| 对比项 | 毫米波雷达 | 超声波传感器 |
| --- | --- | --- |
| 使用的波 | 电磁波 | 声波 |
| 常见频率 | 24 GHz、77 GHz、79 GHz | 约 40 kHz |
| 典型探测距离 | 几十米到上百米 | 几十厘米到几米 |
| 距离测量 | 支持 | 支持 |
| 速度测量 | 擅长，可利用多普勒效应 | 通常不用于高精度测速 |
| 角度测量 | 能力较强 | 能力相对较弱 |
| 典型应用 | ACC、AEB、BSD、LCA | 倒车雷达、APA |
| 主要优势 | 探测距离远、可测速、受雨雾影响较小 | 成本低，适合近距离泊车 |

### 3.2 L2+ 传感器方案与集中式架构

资料中的 L2+ 方案通常采用 `5V5R-12USS` 或 `10V6R-12USS` 等组合：

| 缩写 | 含义 |
| --- | --- |
| V | Vision，摄像头 |
| R | Radar，毫米波雷达 |
| USS | Ultrasonic Sensor，超声波传感器 |

例如，`5V5R-12USS` 表示 5 个摄像头、5 个毫米波雷达和 12 个超声波传感器。12 个超声波传感器主要覆盖车身近距离区域，为泊车和低速避障提供信息。

![L2+ 传感器布置与 ADAS 架构](picture/Pasted%20image%2020260909173745.png)

从系统架构看，ADAS 正在从多个独立 ECU 的分布式方案，逐步发展到由 ADAS 域控制器统一处理感知信息的集中式方案。传感器数量增加后，集中式架构能够统一处理数据、减少重复控制器，并便于实现行车与泊车功能融合。

![ADAS/APA L2+ 车型方案示例](picture/Pasted%20image%2020260909174300.png)

本周还结合 5V5R 行泊一体控制器框图，梳理了摄像头、毫米波雷达、超声波传感器、显示、CAN FD 和以太网等接口与 SoC 的连接关系。

### 3.3 AK1 与 AK2 超声波方案

与传统超声波传感器相比，AK1 方案增加了信号处理、通信接口和诊断功能。资料中的 AK2 方案在此基础上进一步面向更复杂的自动泊车场景，主要关注：

- 更远的探测距离；
- 更强的抗干扰能力；
- 更快的测量刷新速度；
- 更好的多探头协同；
- 更高的功能安全能力；
- 对 APA、HPA、AVP 和行泊一体应用的支持。

多个超声波探头同时发波时，不同探头的回波容易混在一起。传统方案通常通过依次发波降低串扰；新一代方案则结合编码或调制，让系统更容易区分不同探头的信号，从而提升刷新率和抗串扰能力。

### 3.4 Elmos 超声波产品路线

Elmos 超声波产品主要可以从通信接口和换能器驱动方式两个方向理解：

1. 通信方式包括 Point-to-Point、LIN 和 DSI3。DSI3 带宽更高、延迟更低，适合需要快速响应的 ADAS/APA 系统。
2. 驱动方式包括 Transformer Drive 和 Direct Drive。Direct Drive 可以减少外部变压器，有利于降低系统器件数量和成本。
3. E524 系列主要位于超声波传感器端，负责换能器驱动、回波处理、诊断和通信。
4. E521 系列主要位于主控侧，作为 LIN/DSI3 Master 或 Transceiver，将多个传感器连接到 MCU。

![Elmos 超声波传感器产品路线](picture/Pasted%20image%2020260910140540.png)

### 3.5 E524.17 的主要能力

E524.17 可以概括为：

> **DSI3 通信 + ASIL-B + 多回波处理 + NFD 近场检测 + 编码/抗串扰 + 自诊断。**

它不是简单地把超声波信号传回主控，而是在传感器端完成换能器驱动、模拟回波放大与滤波、数字信号处理、事件提取和诊断。

#### 功能安全

- 芯片按照 ASIL-B 功能安全目标开发；
- DSI3 通信包含 CRC 校验；
- 回波结果可以附带可信度信息，供上层控制器判断数据可靠性。

#### 测量性能

- 资料给出的覆盖范围约为 10 cm～7 m；
- 一次测量可处理 30 个以上回波；
- 支持近场检测、多个回波事件提取和目标特征判断；
- 内部集成 ARM Cortex-M0 32 位控制器；
- DSI3 通信速率最高约为 444 kbit/s，带宽和响应速度高于 LIN。

#### NFD 近场检测

目标距离过近时，换能器发射后的余振还未结束，目标回波就已经返回，两者容易混合，导致系统难以精确计算距离。NFD 的作用是：

> 即使无法得到准确距离，也能及时通知 ECU：车辆前方已经存在非常近的障碍物。

#### 障碍物与信号来源判断

E524.17 可以结合多个回波、多个传感器和不同传播路径，辅助判断目标是低矮障碍物还是较高物体；通过编码和信号特征，还可以帮助区分本车探头发出的信号与其他车辆产生的超声波干扰。

### 3.6 回波事件与距离异常分析

E524.17 会将回波包络线与阈值曲线进行比较，并把关键变化提取为事件：

![E524.17 回波包络线与阈值事件](picture/Pasted%20image%2020260910175245.png)

| 事件 | 含义 | 通俗理解 |
| --- | --- | --- |
| EVT1：TLH | 包络线从阈值下方上升到阈值上方 | 一段有效回波开始 |
| EVT2：MAX | 阈值以上的局部最大值 | 第一个回波峰值 |
| EVT3：MIN | 阈值以上的局部最小值 | 两个峰之间的谷值 |
| EVT4：MAX | 后续局部最大值 | 第二个、幅值更大的峰值 |
| EVT5：THL | 包络线从阈值上方下降到阈值下方 | 一段有效回波结束 |

这些事件可通过 PDCM RCC Frame 7 返回，其中 `EchoType` 表示事件类型：

| EchoType | 事件 |
| ---: | --- |
| 0 | TLH |
| 1 | THL |
| 2 | MIN |
| 3 | MAX |

实际测距中，如果程序总是选择最早的 TLH 或 MAX，就可能把探头发射后的余振当成真实目标。典型现象是目标已经移动，但测量结果仍停留在 12 cm、16 cm 等固定短距离，或者在几个短距离之间跳动。

这一问题通常与以下因素有关：

1. 发射后的余振未结束，早期事件并不是真实目标回波；
2. 近距离阶段的 STG 阈值过低，余振或噪声容易越过阈值；
3. 早期 STC 或测量增益过高，进一步放大了余振和噪声；
4. 回波筛选逻辑只看“最早事件”，没有结合时间窗口、幅值和事件类型判断。

后续可按测量阶段调整参数：

```text
发射后早期：提高阈值或设置屏蔽时间，避开发射余振
余振结束后：逐渐降低阈值，开始检测真实目标
远距离阶段：结合信号衰减，提高增益并控制噪声
```

## 五、总结

本周完成了 RA6M3 LCD 显示链路和 ADAS 超声波生态的系统学习：显示部分从像素格式、帧缓冲区和 GLCDC 时序延伸到背光 PWM 与画面撕裂；ADAS 部分从传感器分工进一步梳理到 Elmos 产品路线和 E524.17 回波处理。通过本周学习，对“底层硬件配置如何形成最终显示效果”和“超声波芯片如何服务于整车泊车功能”建立了更完整的理解。
