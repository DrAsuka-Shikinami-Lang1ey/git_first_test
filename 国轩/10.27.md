## SPI
```
CS 拉低
  → 发送 9F，告诉 Flash 要读 ID
  → 发送三个 FF，同时接收三个 ID 字节
```


**FLASH_nWP 是 Flash 的硬件写保护引脚**，`n` 表示低电平有效，也常写成 `/WP` 或 `WP#`

后面的三个 `FF` 是为了产生 **24 个时钟，让 Flash 把三个 ID 字节送回来**

### MCU DataFlash模拟EE
用软件管理 Flash，让应用能够按参数编号保存、更新和读取数据

|存储位置|目前的用途|断电后数据|
|---|---|---|
|RAM|`g_hsi_system_tick_ms` 等运行变量|不保留|
|外部 SPI Flash|之前读取 JEDEC ID 的芯片|保留|
|MCU 内部 Data Flash|本次用于模拟 EEPROM|保留|

## 
| 属性                  | 设置值                                  | 原因                         |
| ------------------- | ------------------------------------ | -------------------------- |
| Name                | `g_vee0`                             | 后面代码通过这个实例使用 VEE           |
| Record Max ID       | `16`                                 | 暂时保留默认值，测试只使用 ID 0；这里不是字节数 |
| Number of Segments  | `2`                                  | 提供两个轮换使用的区域                |
| Start Address       | `BSP_FEATURE_FLASH_DATA_FLASH_START` | 使用芯片定义的 Data Flash 起始地址    |
| Total Size          | `BSP_DATA_FLASH_SIZE_BYTES`          | 使用芯片定义的 Data Flash 容量      |
| Reference Data Size | `0`                                  | 本次不使用专门的参考数据区              |
| Callback            | `vee_callback`                       | 接收 VEE 的状态通知               |
起始地址：0x40100000
总容量：8192 字节

这个方案将整个 Data Flash 专用于 VEE。两个区域会轮换使用，并且要保存管理信息，不能把 8192 字节全部当作用户数据容量

## 添加底层 Flash 驱动
你的应用代码
    ↓
g_vee0：管理保存的记录
    ↓
g_flash0：执行实际的 Flash 操作
    ↓
MCU 内部 Data Flash


这就是启用 BGO 的原因。Data Flash 操作期间，程序仍可使用 Code Flash 和 RAM，但不能同时读取正在操作的 Data Flash；所以读回必须安排在完成之后。


BGO 是 Background Operation，意思是“后台操作”

| 模式         | 程序执行过程                                      |
| ---------- | ------------------------------------------- |
| **关闭 BGO** | 调用保存 → 等待 Flash 操作结束 → 函数返回 → 继续其他任务        |
| **开启 BGO** | 调用保存 → 启动操作后函数返回 → 继续其他任务 → Flash 完成后通过中断通知 |
|            |                                             |


**VEE 软件管理**来实现这些功能。VEE 负责记录更新、空间轮换和擦除，应用按记录 ID 保存、读取即可
`Record Max ID = 16` 表示可以使用 **ID 0～16，共 17 个记录编号**
物理擦除通常等到轮换回收旧段时，按整个段处理

所以不是 ID 超过 8，也不是累计用户数据必须恰好达到 4096 字节；管理信息也会占空间
