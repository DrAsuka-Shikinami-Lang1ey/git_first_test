## URAT

缓存区必须存满1024字节才发送

**解决方案**
在r_Config_UART1_interrupt_receive(void）中修改接收逻辑**



定义了 MAX_FRAME_LEN = 1024，接收缓冲区和发送缓冲区均为 1024 字节

| **取消固定长度阻塞**               | 不再死等1024字节，改为**逐字节存入缓冲区**，实时判断帧结束                       |
| -------------------------- | ------------------------------------------------------- |
| **帧定界符 `\n` / `\r`**       | **串口助手通常以换行符表示“发送完毕”，单片机检测到此字符即触发 `rx_flag=1`**         |
| **精确回传 `rx_count` 字节**     | **`R_Config_UART1_Send(..., rx_count)` 确保发几个收几个，不拖泥带水** |
| **溢出保护 `rx_count < 1024`** | **防止异常数据流导致缓冲区越界写崩程序**                                  |
```
while (1) { if (rx_flag == 0) {
            R_Config_UART1_Receive(g_rx_temp, 1);
             rx_flag = 1; }
```
**在最初代码中，变量定义为uint8_t rx_flag = 1;，导致在while中的if判断语句永远无法达成条件，程序无法进入，无法跳转到中断函数中，被“困死”在while循环中。


**解决办法**
void r_Config_UART1_callback_receiveend(void)
{

rx_flag = 1;


}
将判断变为是否等于1，初始化标志位为0，然后如果进入到callback_receiveend就将他置为1











程序启动后先调用 R_Config_UART1_Receive(g_rx_buffer, MAX_FRAME_LEN) 进入接收状态；接收中断每收到 1 个字节就写入缓冲区并使 rx_count 自增，当检测到换行符 \n 或回车符 \r 时，认为一帧数据接收完成，置位 rx_flag；主循环检测到 rx_flag==1 后，将接收到的数据复制到发送缓冲区，再调用 R_Config_UART1_Send(g_tx_buffer, rx_count) 回传，从而实现 UART 回显收发


UART 空闲状态为高电平。发送一帧数据时，先出现 1 位低电平起始位，然后依次发送 8 位数据，最低位先发，最后是 1 位高电平停止位。


错误检查
1. 先查串口参数是否一致。两端必须完全一致，包括波特率、数据位、校验位、停止位。本工程是 9600, 8N1。
2. 查 TX/RX 接线是否交叉。单片机 TX 要接上位机 RX，单片机 RX 要接上位机 TX，同时地线 GND 必须共地。
3. 查发送数据是否带结束符。当前接收完成条件是检测到 \n 或 \r，如果上位机发送 1K 数据但末尾不带换行/回车，程序不会判定一帧结束，自然也不会回传。
4. 查缓冲区长度是否越界。当前最大帧长是 1024，如果发送超过 1024 字节且没有及时结束，可能导致后续数据无法按预期处理。
5. 查中断是否正常进入。如果接收中断没进，通常要检查中断使能、全局中断开关、向量表和通道号配置。


SPI
四种模式时钟是空闲电平和数据采样边沿不同组合，要在正确的升降边沿采样，使用MSB时，第一个采样到的位是字节的最高位，最后一个是最低位
1. Mode 0：CPOL=0, CPHA=0  
    时钟空闲低电平，第一个边沿采样，第二个边沿改变数据。
    
2. Mode 1：CPOL=0, CPHA=1  
    时钟空闲低电平，第一个边沿改变数据，第二个边沿采样。
    
3. Mode 2：CPOL=1, CPHA=0  
    时钟空闲高电平，第一个边沿采样，第二个边沿改变数据。
    
4. Mode 3：CPOL=1, CPHA=1  
    时钟空闲高电平，第一个边沿改变数据，第二个边沿采样。

## CSIH的区别
CSIH 的特征：
- 有更多控制寄存器
- 有硬件片选选择
- 有 setup / hold / inter-data delay
- 有 slave select / handshake 这类功能
- 适合更复杂、规范的 SPI 主从通信

CSIG 的特征：
- 寄存器集合更简单
- 更像“简单同步串行接口”
- 适合简单 SPI，不像 CSIH 那样强调多片选、多时序控制、排队式传输
